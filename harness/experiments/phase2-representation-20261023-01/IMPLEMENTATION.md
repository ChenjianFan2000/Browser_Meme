## I0：登记和不可变产物

负责人：主 Agent／通用 Harness 实现者。

在选定并登记的通用 Harness 上新增版本化登记；旧 [phase2](../../phase2/README.md) 仅作接口参考，不覆盖老协议。记录 lineage、构建重复、候选格式／模型族、split group、对象及模板泄漏组、输入包与模型哈希。将计划种子和实际模型采样参数分开。

验收：缺少镜像／快照／oracle／输入哈希或存在未填字段时拒绝启动；run_id 已存在时拒绝覆盖；登记一经运行不可原地改写。所有案例提前占据分母，未运行也产生状态行。相同证据两次构建不会被误计为两条 lineage。

## I1：统一预测回执与 raw/final 双通道

主要关联：[evaluation_broker.py](../../phase2/evaluation_broker.py)、[prediction_record.py](../../phase2/prediction_record.py)、[browser_runtime.py](../../phase2/browser_runtime.py)。用新协议分支或新版本模块实现，保留历史重放语义。

- E/T/C 使用统一最终预测结构与相同 LLM 权限；取消新实验中仅 A 需要原样提交代码输出的约束。
- C 先保存不可改写的 raw 输出、模型／输入哈希，再保存 final 输出和逐字段 override；没有调用代码也必须明确记为未使用，不能伪造来源。
- 支持场景、动作步骤、短序列预测；同一评价单位只能提交一次，收到回执后才允许相应业务动作。
- 模型执行无网络、无浏览器、无私有文件；输入仅是已允许观察、动作和状态。
- raw 推演在初始化序列化后另起进程，仅提供冻结代码、状态与查询；原始历史和缓存不能旁路访问。通用比较器由两场景预测生成 Q×R 范围内的 raw 等价判断，不读取真值。

验收：拒绝动作后预测、其它 case 回执、篡改模型、重复覆盖；raw 与 final 可以不同且两者都被计分。测试用通用假环境和样例字段，不由主 Agent 写目标站点规则。

## I2：持久终止锁与真实预算

主要关联：[browser_broker.py](../../phase2/browser_broker.py)、[process_guard.py](../../phase2/process_guard.py)、[call_records.py](../../phase2/call_records.py)。

所有调用先写不可变尝试记录再校验。区分普通语法／定位错误与终止性权限／预算错误。终止锁跨会话和进程重启持久化，禁止同一 run_id 续跑。模型响应、工具调用、UI 动作、等待、检索量、构建成本分别计数。

验收：用明确属于终止条件的脚本／请求触发拒绝，之后任何执行均拒绝；进程崩溃后锁仍有效；普通可修复错误在预算内可恢复；后台进程清理无法确认则不继续。单次 CLI 启动不误作一次模型调用。无法采集的计量字段在注册前明确调整，不能默认为满足。

## I3：独立网站真值与挑战集

负责人：另起独立 `gpt-6.1-sol` 评价上下文，可读取目标源码；其输出目录与学习者隔离。主 Agent 只验接口和证据，不替它提炼业务规则或选择器。

评价者先交付私有 case schema、对象与工作流分组、Q/R、允许的 UI 初态输入、动作意图、目标身份、独立执行脚本和 oracle。明确何种观测支持持久性／UI／副作用结论，确定等待上限与重置完成条件。

检查每类配对是否在该站可构造；无法构造的项明确列出，受控变体单独登记。独立 oracle 不能调用候选模型或其 parser；后台真值与浏览器读出分别核验。加入正／负／无效果／错误对象的 oracle 校准，不把所有参考答案都由同一自然语言解释器生成。

验收：同一中立输入包可供所有预测组读取；动作脚本在预测之前冻结；一次真值可以安全配对到全部候选；独立克隆的组合任务初态一致。每个业务性质具有原始证据或私有状态出处。私有校准运行与其成本另存，未通过不启动性能比较。

## I4：共同证据、内容匹配与候选构建

负责人：通用导出工具由主 Agent 实现；网站命题／规则／代码由独立学习模型生成。

- 保留原始探索档案，再导出不含探索者推理及规则总结的 E 包；索引只用通用检索，不偷偷做规则摘要。
- K 是独立模型从 E 提取的候选命题。文本生成器按 F0/F1/F2 构建，交命题对应表；同样的未知和例外不能在格式化时变成确定结论。
- M0/M1/M2 共享外部接口和输入权限，自行学习内部字段；用可读的约束审计区分架构偏离与实现错误。
- 记录 K→文本→代码对应，由独立上下文核对；本批 K 不变，新增业务假设计作内容偏离。T/C 绑定相同知识版本和文本文件哈希。若需 K′，必须在解封前另建共同批次并全部重建，不能逐候选增补。

验收：证据包哈希对齐；每个构建只读指定 lineage；没有从 D/H 答案回填；两次构建独立上下文，失败不能自动换第三份；规则书长度和实际成本可测。对应检查只能证明表达忠实性，不打“全规则正确”勾。

## I5：成对调度、解封与报告

负责人：通用调度和报告实现者。

调度必须先收齐同批预测再执行／解封真值，按预注册次序或平衡随机次序运行组合臂。原子测试每对新上下文，同时输出两个场景预测和一个等价判断，隐藏配对类别与预期差异；预算按一对合计。组合测试每案例新上下文，冻结学习包；案例内 LLM 可监督纠错，案例间无评分记忆。按证据包、case、配对、工作流和 lineage 保留关联，防止伪独立。

报告至少包括：固定总分母、原始／最终预测、未知／无效／真值未确认分解、错误合并／无谓区分及其分母、任务与副作用、构建偏离、代码使用／覆盖、分族结果、每 lineage 差值、实际资源和所有失败。

验收：一个全 unknown 模型不会得到“100% 正确”主结论；一个全合并模型在差异对中被识别；一个 oracle 不可判案例不会消失；final 改对 raw 错误的情形不会记为代码正确；数据行数与计划的400评测 episode区分未运行和已完成。

## 实施顺序与停止点

1. 先做 I0–I2，以通用假环境验证回执、隔离、终止和计量。
2. 并行委派 I3，实施 I4–I5；网站私有产物不能进入通用代码示例或学习合同。
3. 实际环境就绪与全部哈希登记后运行 P0，修复基础设施问题并单列重试版本。
4. 依次进行 D1、D2、D3，记录明确的选型理由；不能绕过内容或隔离失败。
5. 冻结方法和全新 H 数据，才开始新的探索与 E/T/C 验证。
6. H 报告冻结后，另行注册适应批次；首次泛化结果永不回写。

本轮设计交付不代表以上步骤已实施。当前最先值得实现的是统一预测通道、终止锁和独立真值合同；单纯增加更多 AX 抽取或扩写规则卡字段不能代替这三项。
