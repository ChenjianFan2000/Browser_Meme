# Cleanup receipts and safe reset admission

This generic increment adds no model call or website task. Prior evidence and gates are preserved.

`process_guard.py` optionally accepts a trusted private receipt path and nonce. Only after `terminate_owned` successfully kills/reaps all owned descendants does it exclusively write and fsync a receipt containing status, zero remaining processes, nonce and supervisor PID. Launcher and broker validate all fields. A failed or SIGKILLed guard cannot produce a valid cleanup claim. Broker receipts live in private/cleanup, outside the executor job workspace. The learner CLI has no private mapping.

Actual generic test 031 confirms successful timeout cleanup receipts and refusal of wrong nonce, wrong PID, absent receipt, and a killed guard without receipt. Test 032 executes a native sandboxed Chromium UI script and receives a valid cleanup receipt. Native sandbox test 035 cannot read that private receipt (ENOENT). Tests 033/034 cover management barrier rejection with pending requests, live reader, callback error, unclosed log or missing cleanup receipt; test 034 drives a real generic HTTP fixture through the relay, including a response callback failure.

The controller constructs exactly three booleans from trusted evidence: relay_drained, browser_tree_clean and gateway_log_complete. The learning completion and preserved learning package checks require all three to be strictly True. Evaluation supplies this object to the independent driver, then requires top-level safe_to_reset to be exactly True as well. Missing fields, numeric 1 and string true do not pass. Unsafe cases retain summary and manifest before stopping; resume cannot skip an unsafe archived case. Wrapper/model CLI exit codes remain separate and neither proves cleanup.
