# 复杂任务真实浏览器模拟：评估介入协议

- 编号：`phase1-complex-pw-20261020-1815`；日期：2026-10-20；接口版本 3。
- 用户要求：继续使用 Solar，执行一个复杂任务，提供完整的操作脚本与评估介入条件。
- 职责：主 Agent 只建设和运行通用 Harness。既有独立 `gpt-6.1-sol`
  作者负责网站规则、复杂任务与脚本；另一独立 Solar 上下文负责部署与评价；
  第三个 Solar 上下文负责公开证据的实时审阅。
  这些上下文已接触过网站源码，本次属于第一阶段源码可见监督演示。
- 依据：[通用监督接口](../../SUPERVISION_CONTRACT.md)、
  [原生脚本接口](../../SCRIPT_CONTRACT.md)与根目录实验方案。
- 站点：保持原始 Discogs 前后端源码，复用已经锁定的依赖和生产构建；
  原始源码、构建资产及数据库基线在准备和运行前核对哈希。
  Playwright 1.56.0，浏览器实际版本逐运行记录，不升级依赖或修改网站来制造通过。
- 环境：`.runtime/phase1-complex-pw-20261020-1815` 使用独立数据和日志；
  依赖、构建从 `.runtime/phase1-discogs-pw-20261020-1633` 只读复用。
  页面地址 `http://127.0.0.1:12042`；后端 `http://127.0.0.1:12138`。
- 固定初态：复制既有冻结基线，SHA256
  `6888037bdcda10c123d0cc99f1eda73501e5f5d5934c99d7d3257f236aa9bd50`。
  不重新生成随机种子或更换账号。使用本地公开 demo 夹具账号，不涉及真实购买或真实账户。
- 固定任务：独立审核后的
  [complex_cases.json](../../sites/discogs/complex_cases.json)。
  目标是在 USD100 预算内，从评分至少95%的完整可见候选集中选两个不同非本人卖家的
  最低总价 USD 报价，各买一件，跨页面回查并完成一次精确结账。
  最优组合与同价决胜、候选完整性、导航历史及副作用要求由公共任务参数固定。
  不绕过网页提交，也不以模型给出的候选或答案代替独立评价。
- 执行：后台无头 Chrome，原生 Python Playwright；1440×1000，en-US，UTC；
  每次运行新进程、新浏览器上下文和冻结数据库初态。禁止 agent-browser、
  重标号元素接口、业务 API 写入、脚本篡改网页或静默重试非幂等动作。
- 初稿 `pw-complex-v001`：1 个任务、19 个 UI 步骤、27 条规则、
  `selection_committed` 与 `before_checkout` 两个计划评估关卡。
  精确规则、步骤、参数、源码、适配器和 Harness 哈希在 `registration.json` 冻结。
- 每步先落盘预测，确认目标、滚动、操作、等待后回读。
  两个关卡分别位于首次入车和唯一结账之前，均实际暂停等待 Solar 决策；
  独立评价全部为真且 Solar 明确继续后，重新采集和评价，并在动作派发前再核对状态。
  任一拒绝、未知、缺失、过期或状态变化均阻止该动作。
- 私有观察：独立评价器可只读 SQLite，核验历史和无关副作用；
  它另行验证本地登录 cookie 的签名、有效期与主体，不向脚本或 Solar 提供 token、
  密钥、数据库快照或私有最优组合。公有 review packet 与
  `private-supervision/` 目录分开。独立上下文与目录约定不是操作系统访问沙箱。
- Solar 只根据冻结公开任务、自己的模型及 review packet 内的真实 DOM、截图、
  浏览器网络反馈、公开计算记录和限定独立反馈判断。
  它生成绑定 request ID 与请求/证据哈希的 `decision.json`；
  主 Agent 不代写判断，不用一个自动 `continue` 文件伪装模型介入。
- 故障：定位、时序、实现、业务反例、无法确认分别诊断。
  步骤错误或矛盾触发诊断并停止；当前运行不能通过修改规则、删除步骤或复点写操作复活。
  必要时作者另存 `v002`，从同一基线完整回归，首次结果仍保留。
- 预算：单条 Playwright 命令30秒；单任务900秒、整个套件1800秒，
  包含评估及等待。每任务最多3次 Solar review，每次至多240秒，
  两次用于计划关卡，一次保留失败诊断。初次运行一次，最多一次网站模型修订和完整回归；
  通用基础设施修复单独记录。完成整条目标、预算耗尽或用户停止时结束。
- 记录：DOM、遮蔽输入凭据的截图、脱敏网络与 trace、逐事件时序、
  公开计算、各次独立评价、Solar 决策、状态复验、规则及脚本版本均保留。
  所有步骤含未执行项保留分母；UI步骤、评估关卡与独立业务终点分别报告。
- 计时：任务端到端包括等待、读回、评价与实际模型介入等待；
  review等待另列，安装/构建/编写另列。调用接口不提供 token/费用时填 `null`，
  不声称零模型调用，也不从耗时臆算账单。
- 范围：本次为单个组合任务的源码可见实测，没有新测试集、统计成功率、
  严格速度对照、阶段二独立学习或官方基准声明。避开的既有网站缺陷没有被修复。

原始任务提案保留在 `public-task-proposal.json`，其中首个关卡最初为不暂停建议；
独立审核和协议 3 将其固定为必须 live review。实际执行以冻结 cases、plan
及本协议为准，提案不冒充最终运行协议。
