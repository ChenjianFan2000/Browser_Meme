# 当前研究状态与云端交接（2026-10-23）

## 最新研究决定

以下设计来自用户本轮提供的研究状态摘要。当前完成的是试验设计，尚未启动这套新方案的真实实验；已有组件合同预实验不能计入新方案预算或成绩。

顺序是**先探索表示，再验证 E/T/C**：

1. 比较规则书格式：自由叙述、结构化规则卡、分层机制手册。命题内容与证据保持一致，避免把多知道一些信息误判为表示更好。
2. 比较可执行表示：局部变化、对象关系状态、历史与竞争假设。
3. 检验抽象失真：外观不同但行为相同、外观近似但行为不同、当前观察相同但历史不同、单步相同但后续不同。
4. 方法冻结后做新 E/T/C 对照：统一 LLM 监督，分别保存代码原始预测和最终预测，识别 LLM 是否补偿了错误模型。

预算为 20 回合链路试跑、200 回合表示筛选、180 回合冻结验证，共 400 回合。探索、真值校准及后续修正另计。三条独立探索重复只支持小规模验证，不能据此宣称发现普遍最优格式。E/T/C 各组的正式定义和配置应以待同步的完整协议为准，不从字母自行推定。

目标保持为：在明确业务域内连续产生一致的 DOM、AX 与业务变化；查询等未知外部数据可用事前结构约束及观察后绑定表示。规则书应同时写清可访问组件的功能与相对稳定的定位方式。允许模型使用语义推理提出假设，再通过真实操作检验和修正。
