# 第一阶段：源码可见、直接 Playwright 白盒实验

- 实验编号：`phase1-discogs-pw-20261020-1633`；协议版本：2。
- 依据：根目录实验方案、研究目标与 AGENTS.md；历史 MVP 保持独立。
- 站点：既有 VeriEnv Discogs 完整前后端。上游源码不修改；
  逐文件哈希、实际安装版本和运行副本一致性在业务执行前冻结。
- 运行目录：`.runtime/phase1-discogs-pw-20261020-1633`。
  使用既有冻结 SQLite 基线的独立副本；基线 SHA256 在输入清单记录。
  基线含随机生成的 UUID/时间戳，以数据库哈希固定，绝不重新种子化冒充相同状态。
- 账号：本地公开示例账号与匿名上下文；每任务恢复基线并建立新浏览器上下文。
- 观察：源码、配置、DOM、属性、可见状态、截图、浏览器网络反馈均允许。
  后台只读观察由独立评估器提供给监控器；脚本不获得后台特权接口。
- 执行：原生 Python Playwright；无头浏览器；不使用 agent-browser 或重标号引用。
  Playwright 版本固定为 1.56.0，实际浏览器二进制与版本运行前记录；
  页面 1440 × 1000、locale en-US、timezone UTC。
- 协调者：仅维护通用 Harness、协议、进程、版本、预算、运行与证据。
  协调者先前上下文已接触网站源码，不充当实验学习者。
- 模型作者：独立 `gpt-6.1-sol` subagent，`fork_turns="none"`，
  完成全站源码阅读、规则书、预测、原生脚本及修订。
  部署和评估由另一个独立 `gpt-6.1-sol` subagent 负责，
  不以模型作者的答案构造唯一评价真值。
- 接口：[SCRIPT_CONTRACT.md](../../SCRIPT_CONTRACT.md)。
  首先固定既有八个公开目标；扩展目标由源码审查形成公开清单，
  在扩展套件首次执行前冻结。不同套件分别记录固定分母。
- 分区：本轮全部属于第一阶段开发、修订和回归；不报告阶段二学习、
  未见组合泛化或官方基准成绩。
- 预算：每套件至多 24 任务、300 计划步骤；每个 Playwright 调用
  至多 30 秒、每任务 180 秒、每套件 30 分钟。初稿后最多两次
  网站模型修订。基础设施修复独立记账，不改写历史结果。
- 重复：初稿实际执行一次；必要时修订并完整回归。
  稳定版本再按原顺序执行两次，分别重置业务与浏览器上下文。
  超时、拒绝、无法确认、未执行项全部保留。
- 停止：预算耗尽、不可恢复的基础设施失败、用户停止、或两次稳定回归完成。
  进程超时须终止本次拥有的子进程，不停止其他项目进程。
- 预测、动作、回读、独立评价均落盘；记录规则—脚本—检查项对应关系，
  实际源码审阅清单、未验证分支、修订反例和副作用检查。
- Token 与费用：运行接口未提供时填 null。当前会话及 subagent 的监督
  记录为实际参与，不声称没有 LLM 调用。业务运行耗时包含等待、回读、
  检查和截图；安装、构建、源码阅读及维护另报。不是严格速度对照。
- 展示：规则书、覆盖与限制、单个完整任务的预测—UI操作—网络反馈—
  持久化状态—独立终点评价证据及可重放脚本。

业务执行前另保存不可覆盖的 `registration.json`，固定套件、规则、
脚本、源码、适配器、运行配置及预算的哈希；新增目标或预算另记协议。
