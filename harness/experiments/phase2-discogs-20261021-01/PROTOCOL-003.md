## 独立 worker

为完成两组各三轮及 180 次逐例独立监督测试，允许最多三个独立部署 worker 同时运行。
这是对最初单数据库串行安排的显式修订：每个 worker 内仍严格串行，三个 worker 不共享可写数据库、浏览器状态、cache 或日志。
它们使用相同 v002 源码、依赖、生产构建和私有任务清单；部署层为每个前端映射并约束其所属后端连接。
必须先通过真实连接边界、跨库写入检查和各自 30 例环境 UI 验收，不能只凭修改端口宣称隔离完成。

种子与 worker 一一固定，A/B 在同一 worker 配对。顺序预先固定：1729 为 A→B，2718 为 B→A，3141 为 A→B。
每次学习前恢复相同学习基线；每例测试前恢复对应私有初态。学习者始终只见同一个公开 origin。
全部六个学习包通过结构、原件哈希检查并冻结后，才允许派发第一例私有测试。
最终 worker 地址、端口、验收与环境哈希写入独占创建的 `FORMAL_SCHEDULE.json`。
资源条件及并行度单独报告，不从本实验推导速度优势；部署监控保留至少 3 GiB 宿主可用内存。

三个 worker 的部署适配均限制外部装饰图片请求，未缓存的封面图片可能无法显示。
这是两组共有的实际观察条件；页面文字、DOM、控件及同源业务请求仍按协议开放。
报告需保留此限制，不能将缺失装饰图片归因于学习模型，也不能声称等同于未受限原站的视觉体验。

## 每例冻结测试

采用逐例新 Solar 上下文，而不是批量暴露全部 30 个目标。每例仅获得自己的 `id/goal/parameters` 和本轮冻结学习包。
冻结包映射为只读；当前任务临时脚本、当前案例内 LLM 监督与故障诊断允许，跨案例反馈及模型/规则更新不允许。
每例上限为 60 个 UI 动作、20 次浏览器脚本执行、900 秒；两组一致。测试顺序以该轮管理种子打乱，A/B 同种子顺序相同。

先允许登录和只读 UI 观察，以识别当前状态。业务写入前必须通过可信工具一次性声明任务级预测。
A 组调用冻结的 `behavior_model.predict(observation, intent)`，工具在离线 namespace 中执行并保留模型及输入哈希；
声明必须与其实际输出严格一致，包括 JSON 类型。B 组使用冻结自然语言规则和当前 UI 观察，由相同 Solar 给出预测，无可执行预测模型。
两组都可在声明后继续监督任务执行并修正临时定位/时序脚本，但不能追溯修改已声明预测或冻结知识。

预测声明经管理专用通道落盘，与实际基线哈希及案例 id 绑定。该控制 socket 不向模型命令工具或浏览器执行进程开放。
声明和 HTTP 请求派发均使用同一 Windows 管理进程的 `time.time_ns()`，派发记录在请求发出前保存；
失败、pending、超时请求也保留派发记录。重复、迟到、绑定错误或缺失的预测不获正确分，原因单列。
任务完成、拒绝、状态差异和无关副作用仍由独立评估确定，不使用模型自己的断言充当真值。

每例结束先关闭浏览器并排空转发请求，再进行独立状态检查和下一次重置。
停止、超时、未知和失败保留在固定分母，不删除，也不根据结果换题。
原始首次冻结成绩不可覆盖；需要额外适应时另记运行，不能混入本次 180 例。

此补充没有改变学习动作/时间预算、模型、观察范围、私有案例或研究边界。
