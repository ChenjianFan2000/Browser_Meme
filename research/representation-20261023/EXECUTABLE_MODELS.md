## [MEMENTO3] Memento 3: Model-Based Recursive Self-Improvement through Reflective Rulebooks

### 来源与复核位置

- 作者：Haoyu Zhao、Zhengxu Yu、Zhiyuan He、Meng Fang、Rasul Tutunov、Haitham Bou-Ammar、Weilin Luo、Jun Wang。
- 年份与版本：2026；`arXiv:2610.11794v1`，2026-10-08。
- [固定版本正文](https://arxiv.org/html/2610.11794v1)；[固定版本摘要与提交记录](https://arxiv.org/abs/2610.11794v1)。
- 作者代码仓库：本轮未核验到作者代码入口；不能据此断言作者没有公开代码。
- 重点定位：§2.1，式(6–9)；§2.2，式(20–21)；§2.4，式(28–31)；§3.2–3.3；§5 Setup、Table 5、Result。

### 原文记录

目标是以冻结 LLM 持续学习规则书与可执行模型。规则书记录实体、动作、动态、目标、未决假设；ARC 实例保存为 `world_model.md`，代码包含 `world_model_engine.py`。程序自定内部状态空间，提供初始化 `ι(o)`、转移 `f(s,a)`、readout `ρ(s)`、目标判断；历史重放恢复当前内部状态。单模型 belief 是模型—状态的点质量，群体扩展是多个此类假设的等权近似。

新证据触发保留、修规则书或仅修代码。ARC 验收结合 LLM 忠实性判断与全历史逐帧 `64×64` 格精确回放。§2.4明确：错误模型若从未访问能揭错的历史，也可一直未被证伪。因此历史匹配不证明未来语义或抽象充分。

定量边界：§4报告25个公开游戏全部通关；分母是这25个游戏。§5固定控制器在3个不同开局回合均为21:0；分母仅3回合。Pong 保留渲染/运动误差，以轨迹诊断和控制结果验证，不能把 ARC 的逐格门槛套到 Pong，更不能套到任意网页。

### Browser_Meme 推导（本轮判断，未实验）

- 可借鉴规则假设与代码实现分离：新增业务理解与纯实现修补应有不同修订原因。但规则书采用 Markdown 不证明该格式最优。
- 状态字段应可修订；保留原始观察与版本化重放证据，才能重新判断早期归纳。完整 AX 字符串相等不应被直接指定为业务语义判据。
- 建议分别测历史一致性、冻结模型未见情形预测、真实任务结果、在线修正；模型群是否改善探索须单独消融，不能由群体形式推定。
- “代码忠实于规则书”的 LLM 评审只能检查两种表述是否一致；不能代替独立环境真值。

### 复习问题

- `ρ(s)`负责什么？为何换内部状态表示后仍可用原观察检验？
- 全历史回放通过，为什么“遇墙停止”和“到某列停止”仍可能无法区分？
- 哪些结果属于 ARC 的精确回放，哪些属于 Pong 的近似预测与控制评价？

## [PATCHWORLD] PatchWorld: Gradient-Free Optimization of Executable World Models for Agent Environments

### 来源与复核位置

- 作者：Jiaxin Bai、Yue Guo、Yifei Dong、Jiaxuan Xiong、Tianshi Zheng、Yixia Li、Tianqing Fang、Yufei Li、Yisen Gao、Haoyu Huang、Zhongwei Xie、Hong Ting Tsang、Zihao Wang、Lihui Liu、Jeff Z. Pan、Yangqiu Song。
- 年份与版本：2026；`arXiv:2605.30880v4`，2026-07-28；首次提交2026-05-29。
- [固定版本正文](https://arxiv.org/html/2605.30880v4)；[固定版本摘要与提交记录](https://arxiv.org/abs/2605.30880v4)。
- [作者仓库 HKBU-KnowComp/PatchWorld](https://github.com/HKBU-KnowComp/PatchWorld)：从论文所给链接进入并核对项目身份；未运行，未固定 commit。
- [作者轨迹数据集](https://huggingface.co/datasets/HKBU-KnowComp/patchworld-trajectories)：保留为后续复现入口，本轮未下载／运行。
- 重点定位：§3，式(1–5)、Fidelity and decision utility；§4.1–4.3、Figure 3；§5.4、Tables 2/4；附录B、G、L、P。

### 原文记录

目标是从离线观察—动作轨迹归纳 Python 模型。接口固定为 `parse_observation`、`init_belief`、`correct_belief`、`predict_belief`、`readout_observation`；§4.1明确不预设 belief schema，由 LLM 提出。确定性 belief 经动作预测，readout 生成文本，再用真实观察纠正。

成功/失败对照用于取样；全验证轨迹产生解析、belief、状态、readout 等类型反例。补丁须严格改善全验证集加权错误分。留出评价另测文本与决策；修复不是形式完备性证明。

同为 Qwen3-Coder-480B、共享选择器与候选动作协议时，Simple→Residual 的 Token F1 为0.57→0.69，成功率为76.4%→72.9%。这仅是该实验中7环境等权宏平均的反向变化：每环境最多200个留出回合、30步上限，不能统一按各200个反推成功次数；F1也不是正确转移比例。附录L：15轮预算内无环境零回放错误。附录P限制为语言环境、确定性 belief、一步前瞻，决策仍依赖 LLM。

### Browser_Meme 推导（本轮判断，未实验）

- 最有用的设计依据是“先固定职责接口，允许表示被修订”。五接口不能预先证明字段足够，也没有替 Browser_Meme 选出最佳字段。
- 可分别检查观察解析、记忆更新、动作后果与观察读出，避免把定位或文本渲染错误一律当成业务规则错误。各项真值须独立于模型自身预测。
- 应同时评价语义差异检测与实际动作选择。高文本相似度可能漏掉少量关键差异；该论文也不支持反向推论“文本保真越低越好”。
- 若抽象器与评分器都删除同一差异，两者可共同失明。保留原始 DOM/AX/截图和真实终点证据，再用受控语义差异检验漏报，属于本研究需验证的扩展。
- 预算终止与零误差收敛要分开记录；改进错误总分不等于每一类别或每条旧能力都未退化。

### 复习问题

- 五个函数分别管理事实抽取、初态、纠正、转移、readout 的哪一部分？
- replay 中用真实观察纠正，与 rollout 中回灌预测观察的区别是什么？
- 0.57→0.69与76.4%→72.9%的比较控制了什么，仍不能推出什么？
- typed counterexample 能定位已暴露错误；遗漏状态差异尚未影响输出时会怎样？

## [WORLDCODER] WorldCoder, a Model-Based LLM Agent: Building World Models by Writing Code and Interacting with the Environment

### 来源与复核位置

- 作者：Hao Tang、Darren Key、Kevin Ellis。
- 年份与版本：2024；`arXiv:2402.12275v3`，2024-09-20；首次提交2024-02-19。
- [固定版本正文](https://arxiv.org/html/2402.12275v3)；[固定版本摘要与提交记录](https://arxiv.org/abs/2402.12275v3)。
- 作者代码仓库：本轮未独立核验，不补写推测地址。
- 重点定位：§2.1；§2.2，式(1–2)；§2.5，式(3)；§3 AlfWorld 与 Figure 5；§5。

### 原文记录

目标是交互学习可用于规划的 Python 转移与奖励函数。状态预先表示为对象集合，如 `name,x,y,open,locked`；程序提供 `T̂(s,a)` 与任务相关 `R̂(c)(s,a,s′)`，后者返回奖励和完成标记。没有通用观察 readout 或从任意观察学习 belief 的接口。ALFWorld 被改写为 PDDL 风格 fluents 的 MDP。

验收约束为解释所有 `(s,a,r,s′,c,done)` 数据，且能规划到正奖励；反例用于代码修复。§2.5用 REx 选择待修程序。其量化搜索分数式(3)分母是 `|D|+|D_sc|`：经验数加初态—目标对数；乐观项须先满足全数据一致性才计入。它不是留出网页成功率。

§3报告 ALFWorld 模型250余行，Figure 5曲线平均3个种子；行数不是准确率分母。本笔记不摘录未核清样本分母的成功率。§5明确依赖确定性动态、符号离散状态；感知及遗漏符号仍是边界。

### Browser_Meme 推导（本轮判断，未实验）

- 可以借鉴“模型解释数据”和“模型支持计划”两种约束，但不能把乐观可达性当成真实网站可达性的证据。预测能完成必须经真实执行核验。
- 其对象状态是已提供的表示前提。因此它不能单独证明从自由 DOM/AX 自动归纳对象、权限、持久化状态和隐藏历史的可行性。
- 若比较预设 schema 与自主 schema，必须把前者获得的表示知识算入实验条件；不得让一个对照预先拿到研究者写好的网站语义却宣称同等学习机会。
- 学习动态与任务完成函数分离值得保留；实际独立评测仍不得由模型作者自己定义唯一完成真值。

### 复习问题

- 精确匹配的是原始网页观察，还是已经符号化的状态和奖励？
- 为什么把 ALFWorld 转为 MDP 会改变它处理部分可观察性的难度？
- 乐观约束怎样促进探索，又为什么不是“模型正确”的充分条件？

## [POEWORLD] PoE-World: Compositional World Modeling with Products of Programmatic Experts

### 来源与复核位置

- 作者：Wasu Top Piriyakulkij、Yichao Liang、Hao Tang、Adrian Weller、Marta Kryven、Kevin Ellis。
- 年份与版本：2025；`arXiv:2505.10819v4`，2025-11-19；首次提交2025-05-16。
- [固定版本正文](https://arxiv.org/html/2505.10819v4)；[固定版本摘要与提交记录](https://arxiv.org/abs/2505.10819v4)。
- [作者项目页](https://topwasu.github.io/poe-world)；[作者仓库 topwasu/poe-world](https://github.com/topwasu/poe-world)：均打开核对；未运行，未固定 commit。
- 重点定位：§3.1–3.2，式(2–5)；§4、Tables 2–4；§6；附录A.1、A.3。

### 原文记录

目标是将小程序专家组合成随机世界模型。输入为对象属性与完整观察/动作历史，不要求统一全局 latent belief。专家对单项属性给值，转成加噪分布；未指定部分为均匀分布，再按加权乘积组合。给定历史后属性条件独立，是使推断可行的假设。

LLM合成专家，轨迹似然优化权重并删除低权重专家；另学习约束排除不可行场景。不是逐观察零误差验收。Table 4的 MR 规划成功由无约束2/9到有约束5/9，MR-Alt由2/9到4/9；每条件分母9次。对应1000随机测试帧的下一观察准确率约0.30→0.31、0.43→0.43，说明此实验中准确率与规划效果不同步。

§4脚注及附录A.3：OCAtari通过逆向游戏RAM得到对象，每款所用游戏还手工修复抽取。§6明确不是直接从像素学习。对象抽取、属性独立与游戏约束不能直接推广成任意网页能力。

### Browser_Meme 推导（本轮判断，未实验）

- 模块化候选规律及可降低权重的局部模型，可能比每次重写整体模型更易诊断；这是可测试方向，不是论文已证明的网页结论。
- 完整历史条件化提示另一选择：局部机制只回查相关历史，不强求所有模块共享一份最小 latent state；实际成本、可追溯性与长历史遗漏应测量。
- 不能假定网页属性条件独立：选择对象、权限与操作可用性可能共同变化。应将分解假设列为待检验项，而不是静默写入评测真值。
- 约束可以改善长程规划却不显著改变平均预测分；应补充不可能状态、关键副作用和组合任务评价，同时披露约束来源及研究者知识投入。

### 复习问题

- 专家未指定某属性时为什么不是断言该属性“不变”？
- 完整历史条件化和一个统一 belief state 分别牺牲了什么？
- RAM与手工抽取修复替模型完成了哪些感知工作？
- 9次规划尝试和1000随机帧衡量不同对象，为什么不能混成一个总体“准确率”？

## 四篇共同留下的开放问题

这四篇提供可执行表示、修复与评价的不同范例，尚不足以选出 Browser_Meme 的最佳规则书格式或语义抽象。需要实验区分三个判断：接口是否可执行、已有证据是否一致、未见行为是否预测正确。

本轮建议把表示与验证的关系作为研究变量：原始证据始终保留，候选模型可以抽象，独立评估通过受控行为差异检验该抽象是否丢失必要区别。若两个真实历史被映成同一状态，但相同操作的业务后果不同，这可作为状态不足的实证线索；它也可能来自真实随机性、观察时序或执行故障，不能未经诊断就断言要加字段。

上述建议不生成目标网站规则，不指定站点业务字段，也没有运行网页试验。具体试验协议、预算和停止条件应另行冻结；冻结后的首次泛化与使用反例后的在线适应分别计分。
