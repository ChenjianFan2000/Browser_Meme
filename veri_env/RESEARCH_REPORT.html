VeriEnv 2026

重建可验证的网站，用成功轨迹训练网页智能体。

环境与验证

Safe and Scalable Web Agent Learning via Recreated Websites

阅读方法、原论文实验、本轮测试与判断

做了什么

WorldCoder 2024

把交互经验编译为 Python 动力学，用一致性和可达性约束推动探索。

程序世界模型

WorldCoder, a Model-Based LLM Agent: Building World Models by Writing Code and Interacting with the Environment

阅读方法、原论文实验、本轮测试与判断

做了什么

以对象状态、动作和目标为输入，合成转移函数与奖励/终止函数。新经验触发代码修订；同时要求历史一致，以及模型认为奖励可达，再通过规划选动作。

实验设置：GPT-4；Sokoban、MiniGrid、ALFWorld。假定确定性环境和跨目标共享的动力学，实验包含迁移、新目标及改动规则。

论文报告 原始数值实验

原论文实验报告结果
Sokoban 模型建立前 50 个动作内；之后执行可不再查询 LLM
模型建立开销约 400k tokens；论文当时约 $15
基础关卡参照ReAct：15% ± 8%；深度 RL 学习 2-box 需 >1M 步

出处：§4.1、Figure 3；迁移见 Figure 4。主文以学习曲线呈现性能，这里不从图上猜一个精确终局成功率。50 动作是模型建立经验量，不是网页成功率；理论依赖确定性、候选类包含真模型等条件。

执行边界：未运行乐观奖励约束、原在线探索循环和规划器。

任务是预测操作后果，而非导航任务完成率

自建本地 issue 网页有 6 条记录、8 类动作：筛选、排序、选择、全选、改标签、关闭、重开、评论。输入包含全部记录（包括被筛掉的记录）、当前筛选/排序/选择/角色/反馈/显示顺序。学习器预测动作后的完整 JSON 状态。

04

失败案例揭示了什么

最有研究价值的信号是：程序可能正确更新业务记录，却没有正确传播到界面与反馈。以下四项均为当前方案修正后，在同 12 条组合的最终状态上分别判定；它们不是互斥类别。

12/12最终业务记录
9/12最终界面状态
9/12最终操作反馈
6/12最终联合完整状态

案例一：关闭之后，列表没有变

筛选 open→选择 issue→关闭

预测中的 issue 状态已正确变成 closed，但 visible_ids 仍保留关闭前的筛选列表。

定位：业务转移正确，界面读出没有按新状态重算。仅检查数据库字段会漏报这个错误。

案例二：成功动作保留旧错误

关闭被 blocked 拒绝→成功添加标签

标签更新正确，反馈却仍为上一操作的 blocked。直接 Luna 的部分轨迹也有反馈未复位问题。

定位：反馈取决于最近一次动作；它不能作为无条件保留的状态字段。

案例三：没有证据的优先级，模型只能猜

新版本中，“没有关闭原因”应先于 blocked 检查。六条适应证据分别展示相关规则，却没有展示两个条件同时成立。WorldCoder 和 Agent2World 派生条件选择了另一顺序，得分为 9/12；其他条件多为 12/12。

研究问题：在证据不足时能否保留两种假设，并主动执行一次“两条件同时成立”的关闭操作来区分？这比继续修一份已经猜定的代码更接近可检验的规律发现。

案例来自 逐例失败记录，不是新补测。下一轮必须使用新的封存测试，不把本轮答案用于修复后再报告首次泛化。

是否知道哪个原论文算法最好？不能判断本轮是单次提示/表示适配，完整搜索、权重和多角色链未保留；预算也非等 token。
主动发现控件、真实网页闭环、速度？尚未检验给定完整 JSON 和动作接口；没有自主对象发现、正式 UI 任务成功率或 UI/API 速度对照。

从所有论文与本轮实验共同得到的认识

程序化、前瞻、可修正性都有已有工作支撑，但没有一种表示天然保证准确。GIF-MCTS 的程序搜索、PoE 的模块组合、PatchWorld 的执行验证、Memento 的规则/实现分诊各自处理不同环节；网页预测论文则展示了前瞻与合成训练的用途。

现在的缺口是把证据获取、假设辨识和跨层验证连接起来。本轮的全观察、固定动作微域已经暴露界面读出与条件优先级问题；真实网页还会增加状态抽象、隐藏信息和异步过程。将这些缺口作为研究假设，比把已有组件拼接后直接宣称新世界模型更有说服力。

05

是否值得继续，以及如何与 VeriEnv 整合

有条件继续：把目标定为“有限交互下，可证伪且可修复的网页行为模型”。

“让 LLM 写一个网页模拟器”已经缺少独立新意。仍值得验证的增量是：更少交互辨识规则、修复业务与读出依赖、以及明确区分假设错误和实现错误。下面是下一轮方案，不是已完成结果。

建议的整合结构

已接通1 · VeriEnv 环境与真值

本地站点、重置、HTTP/SDK、私有任务与原 judge DSL；独立保存真实转移。

已有基础2 · 代码预测与回放验证

统一 predict 接口、冻结产物、严格状态比较；PatchWorld 原生验证钩子。

待实现3 · 假设—交互—修复闭环

保留未决规则，选最小区分操作，诊断规则/实现/状态估计，再验证补丁。

建议的信息流：页面证据 → 假设与预测 → 提交后执行 → 独立差异检查 → 定位与修订 → 回归验证。评测真值始终由环境层持有；不向学习器暴露测试答案。

1

先验证业务转移与界面读出的组合一致性

对照单一转移函数、独立读出函数、显式依赖关系与局部重算。保留筛选/排序/批量修改/失败恢复等从未演示的组合模板，分别计业务、界面、反馈与联合正确率。

通过条件：在相同证据与修复预算下，未见组合稳定改善且不损害业务预测。若优势仅来自多给反例，或等预算文本记忆达到相同结果，就不能归因于程序结构。

2

允许主动选择能区分假设的交互

比较随机探索、LLM 不确定性探索、模型分歧驱动的区分试验。受控改变校验优先级、批量原子性、选择保持与评论幂等性，划分未见规则组合。

通过条件：固定查询数下识别更多真规则，或用更少真实交互恢复准确预测；同时检查“不知道”的校准。猜中一次、补丁命中一组案例不构成主动辨识证据。

3

公平检验代码、文本规则书和二者结合

至少四组：直接预测＋历史、文本规则书、可执行代码、规则书＋代码。全部得到相同新增证据和开发反馈；分别记录规则修订与代码修补。建议至少 5 次独立生成、20 个对象种子，按任务族/版本组合统计。

通过条件：改善在多个生成重复和新规则组合上仍存在，且计入调用、token 与维护成本。若等预算直接预测消除优势，调整机制主张。具体规模与阈值在下一轮运行前冻结。

4

接回完整上游机制，再扩展到真实页面观察

优先接 PatchWorld 原诱导/反例选择与 WorldCoder 原约束；GIF 要真正运行树搜索，PoE 要拟合专家组合，Agent2World 要保留研发与测试链。随后隐藏业务 SDK，统一给予 DOM/无障碍树和浏览器动作，增加分页、详情页与延迟保存。

通过条件：先完成浏览器端到端验收，再分别测控件发现覆盖、预测、闭环任务和维护。WMA/WebEvolver/WebWorld 的专用权重实验单列；Code2World 另设视觉渲染评价。

什么时候应该缩小或停止这条主张？若等证据、等反馈、预算受控后，代码/规则书没有稳定收益；主动试验无法更有效区分规则；或只在固定 JSON 接口成立、迁移到页面即失效，就不应继续主张“更通用的网页理解”。可转为范围更清楚的测试生成、行为回归或页面读出一致性工具。

速度实验应单独开展：通用浏览器 agent、模型辅助 agent、手写 UI 脚本、SDK/API 在相同初态与业务终点比较，计入等待、验证、重试、学习和维护成本。当前微秒级代码推演只能说明内存函数便宜，不能换算成网页端到端加速倍数。
