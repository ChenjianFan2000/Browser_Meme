这是 `component-contract-pilot-20261023-01` 的历史工程交接包。它保存一个网站上的表示探索、真实失败和修订终点，供新会话理解方法、检查通用 Harness 和继续工程研究。**当前证据是 v006 的 3 个固定任务完成 1 个，另 2 个在阅读点停止；007 修订没有执行浏览器。** 本包不证明找到了普遍最优表示，也不证明代码模型因果性地提升了理解。

## 当前表示能表达什么

这次探索形成的是组件契约与共享状态模型：对稳定区域和定位方式作明确约束；对查询结果预先声明 0 到 N 个对象、每个对象应有的结构、类型与位置，再从真实观察绑定值；DOM 与 AX 的对应关系限制在已声明的结构区域。它没有承诺逐字符复制整页 AX，也没有预知搜索结果条数。

真实动作前，消费者调用同一预测程序获得动作及预期变化；动作后由通用 Harness 对照结构、独立业务事实和副作用约束。遇到新内容需要语义判断、对象所有权不能确认或未支持的写操作时，消费者可以停在阅读点。安全停止与完成业务目标分别计分。

实体候选与历史登记比纯文本规则更有表达力，但当前没有从公开卡片属性中发现稳定的服务端实体 ID。丰富的可见签名仍会变化，同正文多对象的候选能表示，针对这些对象的写操作尚不支持。外部状态回读不给先验预测分数，也可能使原业务增量基线失效。

## 007：保留修订，不能宣称成功

007 原样复用 task03 脚本、检查点声明和 v006 模型，只修改 `helpers/driver_v5.py` 的详情归属检查：在唯一详情区域内检查精确标题，再用锚定的复合元数据匹配公司、地点及工作模式。静态 AST / 策略检查记录为通过，实际浏览器动作 **0**。

该轮有两个独立问题：交接清单把允许修改的 helper 输出同时当作不可变输入，导致输入/输出哈希冲突；随后调度包装器又被剩余时间门槛拒绝，在准备、重置和浏览器启动前停止。已冻结预算是 20 个动作、200 秒运行墙钟，其中清理预算 45 秒，另保留 60 秒收尾，所以启动前至少需要 260 秒。脚本的旧 300 秒声明不覆盖引擎实际 200 秒上限。

007 目录只有 task03 脚本；检查点文件仍包含 01/02/03 的历史声明，但该轮仅登记 task03。不能因文件中出现其他任务而扩大执行分母，也不能把 006 的 1/3 改成 2/3。

## 本包为什么不能开箱重放网站实验

这里保留模型、消费者和脱敏汇总；没有发布目标网站源码与部署、受控账号和初态 fixture、独立 oracle、原始 DOM / AX / 截图 / 轨迹或私有重置凭证。证据摘要及其来源哈希可用于交接和核对，无法替代缺失的原始评估材料。

通用运行入口是 [contracts_v3 runner](../../../replica/contracts_v3/runner.py)，但它复用 v1 runner 并依赖 v1/v2 校验器、通用监控、传输、资源管理、租约、Playwright runtime 等文件。只复制 `contracts_v3/` 不构成可运行 Harness。保留的通用 [v3 说明](../../../replica/contracts_v3/README.md) 和 [Playwright runner](../../../replica/runner_playwright.py) 需要结合完整 `harness/replica/` 阅读。

原运行依赖固定 Playwright **1.62.0**、固定 core bundle 哈希、Linux `bwrap` / namespace 以及本机 Python、Node、Chromium 路径，例如 `/opt/codex/runtimes/codex-primary-runtime/dependencies/python/bin/python`、`/opt/codex/runtimes/codex-primary-runtime/dependencies/node` 和 `/usr/lib/chromium/chromium`。部分 runtime 清单保留旧 `work/` 预检记录。这些不是随本包发布的可移植运行环境；环境路径或依赖有改动时，应重新冻结并验收通用运行时。

消费者入口为 `run(h)`，需要 Harness 提供页面、受控 fixture 和动作门槛，不是直接 `python consumer_01.py` 即可重放的脚本。新运行应显式登记模块映射：`components_v4` 指向本包 `model-v006/components_v4.py`，`driver_v5` 指向选定消费者目录的 `helpers/driver_v5.py`；同时登记本包结构契约、检查点声明与独立 oracle。不能用模型自己的预测作为唯一真值。

原模型清单中的 `parent-v005/MANIFEST.json` 仅是被冻结的版本沿革引用；父包没有随精选包发布。规则或消费说明里提到的历史报告也不自动成为运行依赖。本包顶层清单才是当前实际发布文件的索引。

## 新会话如何接手

1. 先读本页、`RESULTS.json` 和原始模型 API，确认这是单站、小样本、可见源码的历史工程试跑，`strict_score` 仍为空；访问隔离有限，不能宣称严格隔离或速度优势。
2. 若继续通用 Harness 工程，保留 `harness/replica/` 中的完整通用依赖闭包（站点私有适配另行准备），在新机器上验证运行时、清理、日志与预算门槛。纯模型 4807 项有限检查和额外 6 项不一致种子检查，只证明已枚举状态内的一致性，不证明网页可达或业务成功。
3. 若继续这个站点，另建运行编号，恢复受控部署与独立 oracle，明确初态、权限、任务分母和观测范围。先修正 007 的输入/输出清单归属、重新冻结哈希和足够预算，再决定是否运行其现有修订。任何真实复跑都生成新结果，不覆盖 001–007。
4. 真实评估至少保留动作前预测、真实 DOM / AX 与业务事实检查、任务目标与副作用判定、耗时及完整清理凭证。遇到错误，按定位、时序、接口、业务规则分类；网站规则和脚本继续交由独立实验模型修订，主协调者只改通用基础设施。
5. 若启动新的独立 E/T/C 表示实验，只把经审查的通用 Harness 交给新学习上下文；隔离本包的规则、任务、反馈和既有站点知识。先探索表示、再冻结方法、最后使用新任务验证。历史工程成功不能填入新实验的结果表。
