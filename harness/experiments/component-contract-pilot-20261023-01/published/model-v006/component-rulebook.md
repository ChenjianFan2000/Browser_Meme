# site_01 规则 v004

这是继承旧产物后的适应探索，isolation_limited、strict_score=null。源证据、反例和版本放侧索引。

- 统一plan先检查状态/guard并输出结构及业务预测；真实动作等待和独立门禁通过后才commit。初态登录编辑允许，未认证protected导航明确拒绝；不猜redirect。
- Search jobs/Location输入改变集合。未知查询的先验只有一个ready结构：结果容器必有，行数未知0..N，每行标题/公司/位置及Save归属必须成立，DOM/AX行底层身份集合相等。零实例子检查not_applicable，不能报通过；未知数据值后绑定，不回写prior。
- Job公开身份仍为完整标题、公司、位置/方式；共同值仍重复则停读。原生合成字符串和合同三文本叶按同一normalizer映射，错误类型/分隔符拒绝。捕获路径只为证据，不是持久对象ID。
- 保存/申请必须先显式选择唯一job并核对详情。已Applied禁用不重试；未知applied/applicants可同脚本从公开详情读取后typed绑定。跨页与刷新要以持久详情验证，不只看列表。
- 相同正文不等于同对象。实体用本地因果handle及公开可变signature登记，观察映射到候选集合；两个候选不能用nth消歧。Like状态/计数等可能暂时区分对象，但不是稳定站点ID。
- 当前post业务动作合同仍要求完整正文唯一。注册了同正文多实体后，body-keyed Like/Comment写操作拒绝，即使当前某个丰富signature唯一；身份表达比现有动作合同更宽，不假装动作已支持。
- 后续观察不得静默忽略：相等记录consistent，冲突默认不改prior并返回contradiction。明确external_update有来源与差异，不计预测成功；无法追溯的反应/评论delta变unknown，相关写操作停止。没有稳定公开身份依据的正文变化不强行配对。
- 不认识的语义、定位歧义、缺桥或合同不确认都停止依赖后缀。新数据本身不要求停读；已知确定策略和唯一身份可连续执行。
