# 冻结评测扩并发与调度交接

2026-10-21，用户在正式评测运行期间明确要求：“大大提速。可尝试尽可能提高并发数量”。本补充在新增 worker 派发首例正式任务前登记；父协议和 `FORMAL_SCHEDULE.json` 原件不改。

## 原件与分母

- 六个学习包已经冻结，结构审查见 `reviews/learning-001.json`。所有原始模型、规则、观察权限、账号权限、私有案例、预测字段和独立评分语义保持原样。
- 登记分母仍为 6 × 30 = 180 例、540 个预测字段。已完成、正在执行和未开始的案例逐项登记到扩容调度快照。已经发生的失败、未知、零 UI 动作和超时保留，不补跑以替换首试成绩。
- `DEVIATIONS-002.md` 仍有效：A2718、A3141 的原 60 例仅作诊断，两个学习包不得进入第三阶段准入集合。并发扩容不恢复其合规资格。
- 本次已出现模型 CLI 的 `workspace routing discovery timed out`。模型进程失败与浏览器业务失败分别披露；正式记录不改写，管理报告另列基础设施可用性。

## 独立 worker 与资源

允许先将总并发由 3 提高到最多 12 个独立 worker。每个 worker 同时只运行一个案例，拥有独立数据库、浏览器状态、cache、日志、端口和私有评估目录。不可并行复用同一可写网站状态。

新增站点沿用冻结源码、生产构建、依赖、基线及任务清单。部署端口注册表和管理 driver 入口可使用独立版本的扩容适配；不得修改冻结业务语义函数。扩容层的代码哈希、实际入口、来源等价检查、真实 UI 验收、连接边界和资源检查另记准入清单。原 namespace/browser runtime 哈希保持不变。

原 worker 的 3 GiB 宿主可用内存下限仍有效。新调度器在派发前检查至少 4 GiB 可用内存，为实际浏览器启动留出空间；不足时等待而不扩大在途任务数。更高并发需先有资源实测和另行登记，不能仅改变数字宣称容量成立。

## 调度交接

旧调度器继续完成当前已启动案例。管理方在其各队列的下一未尝试案例路径放置显式的行政 reservation，使冻结旧控制器在现有 fail-closed 检查处退出，不启动下一次重置。该 reservation 没有模型上下文、初态、动作或评分，不是案例尝试；原件保存在 `batches/drain-001`。

确认旧控制器结束、当前案例安全封存后，将只含行政 reservation 的目录原样移入交接证据区，再允许新调度器派发该尚未尝试的案例。不得删除任何真实部分运行目录或覆盖已有 manifest。旧批次因本次交接产生的非零退出单独记录为管理交接，不冒充业务失败。

新调度器按六轮交错的固定队列领取任务；各轮候选顺序由原种子和原 30 个案例索引产生。A/B 同种子保留相同的队列次序。并行开始、完成和实际 worker 归属另存日志，不再声称每轮测试按原三 worker 串行完成。

每个领取只对应一个全新案例上下文和独立恢复的初态。已封存案例先校验身份、manifest 和重置安全状态后跳过；存在真实未完成目录、未知重置安全或重复领取时停止并留证。不得通过重新执行来消除首试失败。

## 执行接口与停止

模型仍固定为独立 `gpt-6.1-sol`、high reasoning。每例 60 个 UI 动作、20 次浏览器脚本执行、900 秒模型执行窗口；直接 Playwright、动作前预测、只读冻结包、当前案例内监督、独立真值和无跨案例反馈等要求不变。

新管理 runner 复用冻结 `run_evaluation` 的案例流程，只以已验收的新版本入口调用扩容 driver。该替换、新 dispatcher 和部署适配的哈希均须登记；不能只以旧文件哈希未变声称实际执行入口完全未变。

若出现模型提供方连接失败，新调度器停止领取新任务，保留在途案例的自然结案和原始状态；连接恢复后以新的批次编号继续尚未尝试的队列。业务拒绝、诚实未知或普通定位错误本身不触发提供方停派。重置安全不明仍禁止后续重置。

## 结果解释

最终报告保留原 180 例 raw 分母、协议合规配对子集及基础设施失败明细，并标注扩容前后的调度阶段。并发资源与执行顺序已经改变，本轮不用于严格速度优势或成本因果比较。实际 token 字段照录，未观测调用数和费用仍为 null。

本补充没有启动第三阶段，也没有将评测反馈用于修订学习包。

## 最终管理接线与资源门槛

扩容入口同时绑定 driver CLI 与 TrustedEvents 的独立事件接收函数。事件接收的记录、加锁与关闭方法仍继承原 Harness；仅通过新注册 loader 选择实际 worker 的原始 evaluator 函数。两处入口均需独立等价与实例归属核验。

派发前同时要求 Windows 至少 4 GiB、WSL 至少 2 GiB 可用内存；共享采样最长缓存 10 秒，采样失败停止新增派发。提供方错误先于普通超时分类检查，包含错误事件及 turn.failed；出现明确服务连接、容量或限流失败时，即使整体案例同时超时，仍停止新领取。

12 是可登记上限。若新增实例验收尚未完成，可以先登记已准入 worker 子集继续执行；扩充集合时另写登记文件和批次，保留前批次并完成安全交接。首次扩容的实例准备及 UI 验收失败也必须保留，不得记为正式模型业务失败或验收通过。
